# 技術架構與原型 BOM

> 對象：自己動手做第 0 階段原型的人（開發主力用 AI）。每一種感測器的原理、位置、耐候與國外前例，詳見 `07-感測器設計說明.md`。價格見 `05-落地執行計畫.md`。

## 1. 系統架構

```
[地墊感測層] ──有線──> [Alishan Sense 模組艙] ──920 MHz LoRa／BLE──> [大樓閘道器] ──4G／網路線──> [Alishan Cloud]
  壓電感測底座條 ×4–6        邊框端部・灌膠電子艙＋獨立電池艙             插電・一棟一台                 積砂模型、門檻
  叉指電容電極條 ×2–3        比較器喚醒・每 15 分鐘彙總                                                 工單、報表
  積水電極（1／5／10 mm）    非金屬天線窗 200×25 mm                                                     ├─> LINE 官方帳號
  NFC 標籤（無電源）                                                                                    ├─> 管理儀表板
                                                        中央氣象署雨量 API（每 10 分鐘）──────────────> ├─> ESG／WELL 月報
```

第 0 階段先簡化：ESP32 同時當模組和閘道器，直接連 Wi-Fi 呼叫 LINE API。

雲端：Cloudflare Workers＋D1（SQLite）＋Pages。Cron 每 15 分鐘判斷門檻、離線偵測、開工單；月報用 Playwright 轉 PDF（要內嵌 Noto Sans TC 字型子集）。1,000 台以內都不用換架構，每月約 US$5。

## 2. 感測方案比較（研究後的結論）

| 方案 | 結論 | 原因 |
|---|---|---|
| FSR402（原提案） | ✗ | 直徑只有 12.7 mm；要偏壓電流；會被鋁條自重長期預壓 |
| **PVDF 壓電膜在中空 PVC 底座條內** | ✓ 主力 | 被踩時自己產生電壓，可以直接喚醒 MCU；道路車軸計數用了幾十年 |
| MEMS 加速度計（ADXL362） | △ 輔助 | 270 nA 很省，但會漏掉 20–50 ms 的腳跟衝擊；適合用來辨識輪子震動 |
| 四角荷重元＋HX711 | ✗ | 地墊是軟的、底下只剩約 2 mm；溫漂比積砂重量還大 |
| ToF（VL53L1X） | ✗ | 最短量程約 4 cm，比凹槽還深；泥水會糊住鏡頭 |
| 超音波 | ✗ | 盲區 2–3 cm |
| **積砂模型＋清坑秤重** | ✓ 主力 | 不受髒污影響；第 0 階段就能上線 |
| **叉指電容電極（FDC1004）** | ✓ 輔助 | 可以量 0–5 mm 薄層；濕的時候失真，只在乾燥時取值 |
| **316 不鏽鋼積水電極** | ✓ | 簡單、便宜；用交流激勵避免電解 |
| NFC 標籤 | ✓ | 毯條更換、到場紀錄 |

## 3. 功耗預算（量產模組目標）

| 項目 | 平均電流 |
|---|---|
| 6 顆 TLV3691 比較器 | 0.45 µA |
| MCU 深度睡眠 | 2–5 µA |
| 每天 2,000 步 × 醒來 3 ms × 5 mA | 約 0.35 µA |
| LoRa 每 15 分鐘上傳一次 | 約 3 µA |
| 電容電極、積水電極每小時量一次 | < 0.1 µA |
| **合計** | **約 6–10 µA** |

電池用 ER18505（約 4 Ah）加超級電容；理論上可用 10 年以上，考慮 70°C 降額後，目標訂為 ≥ 5 年。

## 5. 原型步驟（約 4 週）

1. **第 1 週：訊號與結構**
   - 把 ES302 樣品放進 2 cm 深的木框當作凹槽。
   - 把 ESP32＋LoRa 放在邊框位置，量 RSSI：蓋上鋁框、不蓋、放地下室，各測一次。
2. **第 2 週：感測**
   - 把 PVDF 膜夾在一條底座下面（先用膠帶固定，還不用做中空擠型），接 10 MΩ＋TLV3691。
   - 用示波器量每一步的電壓，並用手動計數器比對 200 步。
   - 在隧道放電容電極，倒入 50／100／200 g 乾砂，看讀數能不能分辨。
   - 積水電極注水到 1／5／10 mm，確認三段都正確。
3. **第 3 週：雲端與 LINE**
   - 建 LINE 官方帳號 → 開啟 Messaging API → 取得 token。
   - 用 Cloudflare Workers 接收 ESP32 的 HTTPS POST；達到門檻就呼叫 push API。
   - 查詢用 reply API（不計入推播額度）。
   - 接上中央氣象署 O-A0002-001 雨量資料。
4. **第 4 週：展示**
   - 在公司門口放 1 週，錄影人工計數當真值。
   - 做一次「曬熱後用冷水沖」的測試。
   - 錄一段「踩上去 → 手機收到 LINE」的影片給董事長看。

**要進第 1 階段的條件**：計步誤差 < 5%；方向正確率 > 95%；電容電極能分辨 50 g 倒砂；蓋上鋁框後 RSSI 有 ≥ 10 dB 餘量。

## 6. 韌體架構（給 AI 寫程式時的規格）

```
開機 → 設定喚醒來源：比較器輸出（每條線一個 RTC GPIO，ext1 任一觸發）＋計時器（15 分鐘）
每次醒來：
  if 喚醒原因 == 比較器:
     記下哪一條線、32 kHz 時間戳 → 存進 RTC 記憶體的事件環形緩衝
     （若 50 ms 內多條線同時觸發且持續 > 1 s → 標記「清洗模式」）
     回到睡眠（< 3 ms）
  if 喚醒原因 == 計時器:
     事件分群：間隔 > 0.8 s 算新的通過；依線序判方向；依停留時間分人／輪子
     每小時：量 FDC1004 電容、積水電極（交流激勵 1 ms）、模組內 SHT40、電池電壓
     組成 JSON {id, t, people_in, people_out, wheels, wash, cap_pf[], water_mm, rh_box, batt_mv}
     LoRa 上傳（SF9–SF10）→ 收到 ACK 才清除緩衝
  積水 ≥ 10 mm 或保全時段有人踩 → 立即上傳
  回到深度睡眠
```

雲端：`積砂 = 人次 × g(雨量) × η × k`；清坑時 NFC 回填砂重，更新 k。門檻跟模擬引擎一致：積砂 ≥ 70% 開清潔工單；濕滑風險高時提醒放警示牌；毯條壽命 ≤ 10% 排程更換；23:00–06:00 有人踩就發入侵警報。

## 7. 第 1 階段：跟親戚胎壓計工廠合作的重點

| 題目 | 要談的內容 |
|---|---|
| 模組艙 | 200 × 34 × 23 mm，嵌在邊框端部；上蓋是 200 × 25 mm 的 ASA／UV 安定 PC-GF30 天線窗；電子艙 PU 灌膠，電池艙獨立、只用矽膠封 |
| 密封 | IP68（1.5 m、7 天）＋IP69K；PU 灌膠（例如 Electrolube UR5608）|
| 壓電底座條 | PVDF 膜層壓後滑入中空 PVC 擠型條、兩端 PU 灌封；胎壓計工廠有沒有做過類似的壓電封裝 |
| 無線 | **920–925 MHz**（LoRa AS923 台灣參數）或 BLE；433 MHz 在台灣只能間歇控制、不能週期傳資料，不適合；閘道器放在大廳 |
| 電池 | ER18505＋超級電容（ER14505 扛不住發射尖峰）；電池壽命的驗證方法 |
| 量產 | 治具、校正流程、出廠測試、品質追溯 |
| 法規 | 優先選已取得台灣 NCC 的模組，只做登錄（NT$1,500）；否則完整送測 8–15 萬、1–2 個月 |

## 8. 測試清單

- [ ] 蓋上鋁框後的 RSSI（晴天／雨天）
- [ ] 灌膠模組浸水 1.5 m、7 天（IP68），以及高壓沖洗（IP69K）
- [ ] 70°C 鋁條被冷水沖：壓電清洗模式判斷
- [ ] 高壓沖洗、中性清潔劑浸泡
- [ ] 荷重：推車、輪椅、板車通過時（ES302 規格就有列這些）
- [ ] 平均電流實測 → 推算電池壽命
- [ ] 積砂模型：每次清坑秤砂，和模型比對（至少 10 次）
- [ ] 並排、成群通過時的計步準確度（影片真值）
- [ ] LINE：推播與回覆的延遲、每月推播則數
